# TopPicks 데이터 신뢰도 검토

검토일: 2026-09-20. 범위: 로컬 PowerShell 추천·검증 엔진, pykrx 수집기, SQLite 저장 경로. Android 자체 분석 경로는 이번 검증 범위에 포함하지 않았다.

## 결론

추가 팩터를 늘리기 전에 현재 데이터의 실제 이용 가능 시각, 거래 가능 여부, 결측을 확정해야 한다. 다음 단계의 수집 우선순위는 **거래일·기업행사 → 수급 수집 복구 → 호가·체결 → 숫자형 컨센서스 변경 이력 → 전체 시장/업종 및 대차 데이터**다. 데이터 품질과 주가 상승 예측 확률은 별도 지표여야 한다.

## 현재 확인한 문제와 수정

| 확인한 문제 | 반영한 수정 |
|---|---|
| DART 금액에서 모든 마이너스를 제거하여 손실이 이익으로 바뀜 | 부호 보존, 괄호 음수 처리, 결측·비정상 숫자는 null. 자본이 0 이하인 종목 제외 |
| 당해 연도 재무 조회 누락 | 당해 연도부터 조회하고 채택한 연도·보고서 코드를 기록 |
| 종가×거래량을 실제 거래대금처럼 사용 | 제공자 거래대금 유지. 수량 수급의 분모는 실제 거래량 사용 |
| 수급 기간 부족·누락 값을 0 또는 완전한 기간처럼 취급 | 5/20/60개 관측치와 결측 검증, 날짜 정렬·중복 검증, 금액 단위 KRW와 실제 기준일 저장 |
| 상세 기관합계에 연기금 명칭 차이·부분 합계가 개입 | 연기금/연기금등 별칭 처리, 7개 구성요소가 있어야 합계 인정 |
| 공매도 API 오류가 정상 수급까지 폐기 | 선택적 데이터 소스별 오류 격리, 공매도 미확인과 대차 미수집을 명시 |
| 당일 생성 파일이면 오래된 수급도 사용 가능 | 수집 시각과 실제 수급 기준일을 각각 검증. 캐시 60분, 원천 기준일 7일 상한, warm start 유효 종목 coverage 100% |
| 일봉 캐시가 장중 조회 이후 갱신되지 않음 | 검증용 일봉 캐시 5분 만료 |
| 손절 후 반등을 D+3 수익으로 계산 | 손절·목표 청산가격 기준 수익, 갭 손절·동일 봉 양방향 도달 보수적 처리 |
| 관망 수익과 실제 진입 수익 혼합 | 실제 진입 성과·튜닝 표본과 가상 관망 성과 분리 |
| DB 저장 시 전체 이력 삭제 | 부분 저장 시 이력 유지, 해시 기반 전체 payload 감사 스냅숏 추가 |

추가 진입 조건은 `entry-risk-v1`로 구분한다. 수급 미확인, 주요 숫자 누락, 2.5% 초과 시가 갭, 비용 차감 손익비 1 미만이면 관망으로 처리한다. 이 수치는 초기 운영 정책이며 최적화된 투자 우위가 입증된 기준이 아니다.

추가 거시지표나 뉴스 감성 데이터는 위 항목 이후에 검토한다. 단기 전략에서는 실시간 체결 가능성과 당시 공개된 수급·실적 변경의 정확성이 우선이다. 데이터 계약이나 신규 외부 서비스 연결은 수행하지 않았다.

## 공통 저장 규격

각 데이터에 `source`, `instrumentId`, `venue`, `eventTime/asOf`, `publishedAt`(제공 시), `collectedAt`, `unit/currency`, `revisionId`, `rawPayloadHash`, `qualityStatus`를 둔다. 공표시각이 없으면 수집시각 이전에 알 수 있었다고 추정하지 않는다. 누락 공표시각을 임의로 생성하지 않는다.

지금 추가한 필드는 기준일·기간·수집시각·단위 및 일부 출처 진단이다. 전체 원천 응답의 불변 저장소와 공표시각 수집은 아직 구축되지 않았다. 신규 수집 시 원본 → 정규화 → 품질검증 → 추천 순으로 저장하고, 정정은 기존 원본 덮어쓰기 대신 새 버전으로 적재해야 한다.

## 수집 추가의 효과를 확인할 방법

1. 동일 날짜·종목·시장 범위의 가격/거래량/수급을 두 제공처에서 대조한다. 단위·수정주가·KRX/NXT 차이를 먼저 맞춘다.
2. 결측률, 수집 지연, 기준일 지연, 필드 범위 오류, 종목별 coverage를 일별로 집계한다. 표본 부족이면 추천 확신을 높이지 않는다.
3. 기존 모델과 추가 데이터 모델을 같은 기간에 병렬 저장하고 미래 정보 없이 평가한다. 1~3일 라벨이 겹치는 구간은 학습·검증 분할에서 purge/embargo로 분리한다.
4. 순수익 기대값, 벤치마크 초과수익, 손실 꼬리·낙폭, 비용 민감도와 표본 수를 함께 비교한다. 날짜 단위 군집/블록 재표본화로 불확실성을 보고한다. 단순 승률 상승으로 채택하지 않는다.
5. '추천 확률'은 미사용 검증 구간의 calibration/Brier score로 확인하고, 데이터 품질 점수와 혼용하지 않는다. 현재 점수 대용 확률은 검증된 확률이 아니다.

## 실제 점검 결과와 남은 문제

- 저장 TOP3 195건, 65개 추천일을 확인했다. 기존 전 건에 `recordedAt`이 없다. 새 필드 추가로 과거 시점 정확성이 소급 입증되지 않는다.
- 기존 최신 추천은 `historicalReplaySafe=false`였다. 운영 리포트 및 과거 DB를 이번 작업에서 다시 쓰거나 소급 보정하지 않았다.
- 삼성전자 1종목의 읽기 전용 실수집에서 수급 0행, 공매도 KeyError, 공매도 잔고 없음이 확인되었다. 별도 인증 진단에서도 **pykrx의 인증 세션이 없음**을 확인했다. 원인이 비밀번호, 계정 상태, KRX 로그인 응답 변경 중 무엇인지는 확정하지 않았다. 인증되지 않은 빈 응답을 데이터 없음으로 오해하지 않도록 수집기 사전 검사도 추가했다.
- 회귀 검증: PowerShell 30개 단언, Python 11개 테스트, 검증→튜닝 통합 8개 단언, 변경된 런타임 PowerShell 6개 파일 구문검사를 통과했다. 통합 검증은 모의 API와 격리 리포트를 사용했다.
- 운영 프록시 재시작·실제 추천 재생성·전체 종목 원천 대조·새 모델의 시계열 외표본 검증은 수행하지 않았다. 수정 코드가 기존 실행 중 프로세스에 자동 반영된다고 볼 수 없다.
- DART 공시 pagination, OFS fallback, 거래소 달력, 거래정지 구간의 D+n 정렬, 기업행사 조정, 시장 충격·포트폴리오 집중도, Android 분석 경로 동기화는 후속 작업이다. 현재 7일 freshness와 16:00/18:00 시각은 보수적 임시 정책이며 공식 거래일·공표 스케줄을 대체하지 못한다.
