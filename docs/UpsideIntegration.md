# 기존 추천 엔진에 독립 상승 근거 접목

2026-09-21 적용. 정책 버전: `short-term-v4-upside-evidence`.

## 반영 위치

기존 후보 분석 → 기존 단기 점수 → 독립 근거 결합 → 통합 선정 점수 → 시장별 TOP10/전체 TOP3 → 기존 위험 조건 + 독립 근거 차단 조건 → 시점별 스냅숏 저장 순으로 연결했다.

기존 단기 점수는 보존하고 별도 `selectionScore`로 선정한다. 가격·거래량 돌파, 지속 수급, 실적 정보 변화는 서로 다른 근거군당 +2점(최대 +6), 시장 방어 국면 -3, 과도한 구조적 손실 위험 -4, 확인된 악재 -6을 반영한다. 최종 조정은 -6~+6으로 제한한다. 이는 초기 연구 정책이며 학습된 가중치 또는 상승 확률이 아니다. 실적 상향과 실적 서프라이즈를 중복 가산하지 않는다.

시장·업종·가격/거래량·수급·실적 전망·공시·공매도·호가·위험 모듈의 세부 결과와 누락/차단 사유를 기존 추천 항목에 함께 기록한다. 업종·공매도·호가 미확인 등 원 엔진의 차단 조건을 이어받으며, 기존 수급·과열·손익비 조건도 유지한다. 독립 근거의 누락을 악재 발생으로 간주해 감점하지 않는다. 누락은 조정 0점 및 진입 차단으로 구분한다.

장기 펀더멘털 점수는 그대로 유지했다. 이번 통합 정책은 1~3거래일 판단용이다.

## 시간과 표시

종목 코드·시장·가격 기준일을 대조한다. 장중 16시 전에는 직전 평일의 확정 일봉을 허용하고 그 기준일을 명시한다(월요일에는 금요일). 공휴일 간격은 거래소 달력 연결 전까지 보수적으로 제외한다. 보고서 및 종목 판단 시각은 미래 자료가 아니고 24시간 이내여야 한다.

TOP10/TOP3 및 웹 단기 목록은 선정 점수를 사용한다. 화면에도 근거 차단 사유를 전달한다. 이전 보정 확률은 감사용으로만 남기며 새 정책의 확률로 표시하지 않는다. 새 정책 검증과 진입 시점 호가 확인 전에는 관망 상태를 유지한다.

기존 자동 갱신과 수동 실행이 겹쳐 발생했던 저장 충돌을 수정했다. 프로세스 간 잠금으로 추천 생성을 단일 실행하고, 임시 파일을 교체하는 방식으로 JSON을 게시한다.

## 운영과 남은 조건

독립 원천 수집은 별도 실행이다. 새 추천 생성은 가장 최근의 유효한 독립 보고서를 읽는다. 현재 30종목 수집 범위 밖의 종목을 분석 완료로 표시하지 않는다.

```powershell
Set-Location D:\Data\Project\TopPicks
.\.venv\Scripts\python.exe tools\independent_upside.py run --limit 30
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\kiwoom_proxy.ps1 -GenerateOnly
```

추가 컨센서스·공시·수급·업종·공매도·호가 연결 계약은 `docs/IndependentUpsideEngine.md`를 따른다. 이 자료를 확충하고 새 정책을 과거 미사용 자료 및 향후 자료로 검증해야 운영 추천으로 승격할 수 있다.

## 확인한 검사

- 접목 검사 16개: 근거 가감·중복·누락·악재·기준일·미래 시각·장중 확정 일봉·손상 파일 등.
- 기존 엔진 검사 30개, 검증 통합 검사 8개, Python 검사 37개.
- Windows PowerShell에서 JSON 생성/교체, 예외 발생 후 잠금 해제, 생성 함수 실행 확인.
- 웹 JavaScript 구문 및 차단 사유 전달 검사. 브라우저 렌더링 검사를 의미하지 않는다.

실제 최신 추천 재생성 결과는 별도 실행 결과 JSON에 기록한다. 코드 검사를 예측 수익성 검증으로 해석하지 않는다.
